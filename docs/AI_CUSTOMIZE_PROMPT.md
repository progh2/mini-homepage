## AI에게 (이 문서를 읽고 있는 당신에게)

당신이 이 메시지를 읽고 있다면, 사람이 방금 이 저장소 링크를 주면서 이 문서를 읽고 진행해달라고 요청한 상황입니다. 사람에게 이 문서 내용을 다시 보여주거나 요약만 하지 말고, 지금 바로 아래 절차를 실행하세요. 지금 만드는 것은 원 저작자(미요Lab)가 아니라 **이 요청을 한 사람 자신의** 미니홈피입니다.

**-1단계 : 원본 저장소면 먼저 내 계정으로, 새 이름으로 복사(fork)하기**

지금 작업 중인 폴더가 이미 사람 자신의 저장소(원본이 아닌 복사본)라면 이 단계는 건너뛰세요. 사람이 원본 저장소 링크(`https://github.com/Pcallpang/meyo-lab`)만 주고 아직 아무것도 복사되지 않은 상태라면, 사람에게 다시 포크해달라고 시키지 말고 당신이 직접 다음을 하세요.

1. GitHub CLI(`gh`)가 설치·로그인돼 있는지 확인하세요 (`gh auth status`).
2. 새 저장소 이름을 물어보세요 (한글 대신 영문·숫자·하이픈 권장). 사람이 정하기 어려워하면 기본값 `mini-homepage`를 제안하세요. `<내 GitHub 아이디>.github.io`로 지으면 하위 경로 없이 루트 주소로 서비스됩니다(원하면 이 방식도 안내하세요).
3. `gh repo fork https://github.com/Pcallpang/meyo-lab --fork-name <정한 이름> --clone --remote` 한 줄로 사람의 GitHub 계정에 새 이름으로 포크하고 로컬로 내려받은 뒤, 그 폴더로 이동해 계속 진행하세요. "meyo-lab"이라는 원래 이름이나 흔적이 새 저장소에 남지 않도록 합니다.
4. `gh`가 없거나 로그인이 안 돼 있다면, 설치(`https://cli.github.com`)와 `gh auth login` 로그인 절차를 안내한 뒤 다시 시도하세요. 그래도 어려우면 GitHub 웹사이트에서 "Use this template" 버튼으로 새 이름을 직접 지어 복사해달라고 안내하세요.
5. `package.json`의 `name`, `homepage`, `repository.url` 값을 새 저장소 이름/주소에 맞게 고치세요.

**0단계 : 이미 채워진 답이 있는지 먼저 확인**

저장소 안에 `docs/나만의-링크트리-양식.md`가 있고 사람이 이미 빈칸을 채워뒀다면, 아래 체크리스트를 다시 묻지 말고 그 파일 내용을 그대로 답으로 사용해 2단계로 넘어가세요.

**1단계 : 하나씩 순서대로 질문하기 (양식이 비어 있거나 없을 때만)**

바로 코드를 고치기 전에, 아래 13개를 **한 메시지에 몰아서 나열하지 말고** 한 번에 하나씩 순서대로 물어보세요. 사람이 답하면 다음 질문으로 넘어가는 대화 방식입니다. 먼저 "총 13개를 하나씩 여쭤볼게요. 필요 없는 건 '안 씀'이라고만 답하시면 바로 다음으로 넘어갑니다"라고 한 번만 안내한 뒤, 1번부터 순서대로 하나씩 질문하세요.

1. 표시 이름 (예: 홍길동, 또는 별명)
2. 첫 화면 소개 문구
3. 왼쪽 아래 파도타기 목록 첫 번째 항목에 들어갈 `도름스 커뮤니티 나의 활동` 링크 주소(URL)
4. 원하는 색감 (따뜻한 크림 / 차분한 파스텔 / 밝은 교실톤 / 진한 대비 중 하나. 각 색상 코드는 `docs/나만의-링크트리-양식.md` 맨 아래 "AI 참고용 색상표"에 있습니다)
5. 왼쪽 프로필 사진 : 자기 사진이나 좋아하는 이미지 파일 (미리 `public/assets/`에 넣어달라고 안내)
6. 미니룸 이미지 : 홈 화면 위쪽에 나오는 이미지 파일 (마찬가지로 `public/assets/`에 미리 넣기)
7. 자기소개 섹션 (소개 글 / 하고 있는 일들 목록 / 연락처)
8. 게시판 탭 : 탭 이름(기본값 "게시판" 등 원하는 이름)과 올릴 앱·글 링크
9. 낙서장 탭 : 탭 이름과 넣을 사진 (파일은 미리 `public/assets/`에 넣기). 사진 없이 오에카키만 써도 됩니다. 탭 버튼이 좁아 이름은 네 글자 이내가 좋습니다
10. 왼쪽 아래 파도타기 목록에 (도름스 활동 링크 외에) 추가로 넣을 링크
11. 미니홈피 배경음악 (유튜브 영상 링크와 곡별 시작 지점)
12. 방명록 예시 글
13. 방명록·방문 수를 실제로 움직이는 Firebase 연결 여부 (직접 Firebase 프로젝트를 만들거나 키를 발급할 수는 없으니, 필요하면 사람이 만들고 `.env.local`에 값을 넣도록 안내만 합니다)

1~4는 사이트가 성립하려면 반드시 필요하니 빈칸이면 다시 물어보세요. 5~13은 "안 씀"이라고 답해도 그대로 다음 질문으로 넘어가면 됩니다(다만 5, 6은 이미지가 없으면 화면이 깨지므로, 정말 안 넣겠다면 기본 예시 이미지를 그대로 쓸지 확인하세요).

연재물 탭은 이 순서에 넣지 말고 묻지 마세요. `src/config/miyotoon.ts`의 `episodes`는 원 저작자의 개인 만화이니 기본적으로 비워 두세요(탭이 자동으로 숨겨집니다). 사람이 먼저 자기 연재물을 넣고 싶다고 하면 그때만 회차와 탭 이름(`profile.storyLabel`)을 물어보고 채우세요.

**2단계 : 코드 반영: 원 저작자 콘텐츠를 먼저 지우고, 받은 답으로 채우기**

지금 이 저장소에는 원 저작자(미요Lab)의 실제 콘텐츠가 예시로 이미 들어있습니다. 이 사람은 자기 것을 만드는 것이므로, 아래를 **먼저 비우거나 지우고 나서** 받은 답으로 채우세요. 그대로 남겨두지 마세요.

- `src/config/linktree.ts`의 `profile` (표시 이름, 소개 문구, 프로필 사진, 미니룸 이미지, 게시판/낙서장/연재 탭 이름, 오른쪽 위 주소 표시줄 문구 `displayUrl`)
- `profileSections` (자기소개) : 답이 없으면 빈 배열
- `boardPosts` (게시판 글) : 답이 없으면 빈 배열
- `photos` (낙서장 사진) : 답이 없으면 빈 배열
- `ownerUid` : 원 저작자 값이 남아 있으면 반드시 비우거나 사용자 본인 값으로 바꾸세요. 비밀글과 그림 가림 처리 권한이 걸린 값입니다
- `waveLinks` : `도름스 커뮤니티 나의 활동` 한 줄만 남기고, 미요툰·미요앱 인스타그램처럼 원 저작자 개인 계정 링크는 지운 뒤 사람이 준 추가 링크만 넣으세요
- `bgmTracks` : 답이 없으면 빈 배열
- `guestbook` : 답이 없으면 빈 배열이거나 사람이 준 예시 글로 교체

왼쪽 아래 파도타기 목록의 첫 번째 항목인 `도름스 커뮤니티 나의 활동`만은 유지하세요. 이 템플릿에는 여러 링크를 모아 보여주는 메인 링크 카드 목록 기능이 없으니 다시 만들지 마세요. 공개 저장소에 개인정보, 비공개 링크, API 키, 환경변수, DoRms 본 서비스 내부 자산은 넣지 마세요.

**3단계 : 확인**

수정 후 `npm run build`로 오류 없는지 확인하세요.

**4단계 : 배포하고 완성된 주소 보여주기**

1. 변경사항을 커밋하고, 사람의 새 저장소로 푸시하세요 (`git push`). 이 저장소에는 `main`에 푸시하면 자동으로 GitHub Pages에 배포하는 워크플로(`.github/workflows/deploy.yml`)가 이미 들어있습니다.
2. GitHub Pages가 활성화돼 있지 않다면 `gh api repos/{owner}/{repo}/pages -X POST -f build_type=workflow` 로 켜세요(이미 켜져 있다면 오류가 나도 무시해도 됩니다).
3. 배포가 끝날 때까지 기다렸다가(`gh run watch` 또는 잠시 후 `gh api repos/{owner}/{repo}/pages`로 상태 확인) 완료되면, 대화의 **마지막 메시지로 실제 배포된 미니홈피 주소**를 사람에게 보여주며 끝내세요. 예: "완성됐어요! 내 미니홈피 주소: https://<아이디>.github.io/<저장소이름>/"
