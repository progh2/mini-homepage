# 키트 개선 내역과 적용 안내

이 문서는 원본 키트([Pcallpang/meyo-lab](https://github.com/Pcallpang/meyo-lab))를 포크한 뒤 고친 것들을 정리한 것입니다. 다른 포크에서 필요한 것만 골라 가져갈 수 있게 썼습니다.

원본에 PR로 보내지 않은 이유는 두 가지입니다. 포크마다 `src/config/linktree.ts`에 각자 개인 콘텐츠가 들어 있어 병합이 어차피 충돌하고, 아래 B묶음(방명록 개편)은 취향이 갈리는 변경이라 모두에게 강요할 성격이 아닙니다.

## 사람이 할 일 (딱 한 줄)

자기가 쓰는 AI 코딩 도구에 이렇게 말하면 됩니다.

> 내 미니홈피에 이 개선 사항을 적용하고 싶어: https://github.com/progh2/mini-homepage/blob/main/docs/키트-개선-내역.md . 이 문서를 읽고 A묶음만 적용해줘.

B묶음까지 원하면 "A와 B 전부 적용해줘"라고 하되, 아래 **B묶음 경고**를 먼저 읽어 보세요.

## AI에게 (이 문서를 읽고 있는 당신에게)

지금 작업 중인 저장소는 이 문서를 쓴 사람(progh2)의 저장소가 **아닙니다**. 다른 사람이 자기 미니홈피에 개선 사항만 가져오려는 상황입니다.

### 절대 가져오지 마세요

아래는 progh2 개인 콘텐츠입니다. 실수로 옮기면 남의 얼굴과 이력이 그 사람 사이트에 박힙니다.

- `src/config/linktree.ts`의 `profile`, `profileSections`, `boardPosts`, `photos`, `waveLinks`, `bgmTracks`, `displayUrl`, `ownerUid` 값
- `public/assets/` 안의 모든 이미지 (프로필, 미니룸, 사진첩, 게시판 미리보기, og-cover)
- `src/app/icon.png` (파비콘)
- `package.json`의 `name`, `homepage`, `repository`, `author`
- `.env.local`, Firebase 프로젝트 값

가져올 것은 **구조와 로직**뿐입니다. 값은 작업 중인 저장소의 것을 유지하세요.

### 적용 순서

1. 지금 저장소가 원본 키트 상태인지, 이미 개인화됐는지 확인합니다.
2. 아래 A묶음을 위에서부터 적용합니다. 각 항목은 서로 독립이라 일부만 골라도 됩니다.
3. B묶음은 사용자가 명시적으로 원할 때만 적용합니다. 적용 전에 경고를 그대로 전달해 동의를 받으세요.
4. 매 항목 후 `npm run build`를 돌립니다.

# A묶음: 바로 적용 가능

설정 작업이 필요 없고, 기존 동작을 깨지 않습니다. 원본 키트를 쓰는 누구에게나 이득입니다.

## A1. firestore.rules 주석이 첫 줄에서 닫혀 규칙 배포가 실패한다

**증상** `firebase deploy --only firestore:rules`가 파싱 에러로 실패합니다. 방명록이나 방문 수를 켜려는 순간 막힙니다.

**원인** 주석을 여는 줄 끝에 `*/`가 붙어 있어, 뒤따르는 설명문이 주석 밖 평문이 되고 마지막 `*/`는 짝 없는 닫기가 됩니다.

```
/* 한줄평(방명록) 보안 규칙입니다. */   <- 여기서 닫힘
   로그인 없이 누구나 한 줄을 남길 수 있고...
   ...                                  <- 주석 밖 평문
   ... 바꾸면 됩니다. */                 <- 짝 없는 닫기
```

**고치는 법** 여는 줄 끝의 `*/`를 지웁니다.

**확인** 주석 블록이 한 번만 열리고 한 번만 닫히는지, 중괄호 수가 맞는지 봅니다.

## A2. 이미지가 표시 크기보다 훨씬 크다

**증상** 96픽셀 썸네일 자리에 1MB짜리 원본 PNG를 그대로 씁니다. `output: "export"`라 next/image 최적화를 쓸 수 없고 컴포넌트도 순수 `<img>`라 원본이 곧 전송량입니다.

**고치는 법** 표시 크기의 2배(레티나)를 긴 변 상한으로 잡고 WebP로 바꿉니다. `sharp`는 Next.js에 이미 들어 있습니다.

| 대상 | 표시 크기 | 상한 |
|---|---|---|
| 미니룸 | 644px | 1280px |
| 사진첩 (4열 그리드) | 152px | 384px |
| 게시판 썸네일 | 96px | 256px |
| 프로필 | 150px | 320px |

경로를 `.webp`로 바꿨으면 `src/config/linktree.ts`의 `preview.src`, `photos[].src`, `profile.photo.src`, `profile.miniroom.src`도 함께 고칩니다.

**확인** `npm run build` 후 `out/` 용량. 이 저장소에서는 13MB에서 1.7MB가 됐습니다.

## A3. 파비콘이 없다

**증상** `src/app/`에 `icon.png`가 없어 브라우저 탭에 기본 지구본이 뜹니다.

**고치는 법** App Router는 `src/app/icon.png`만 두면 자동으로 파비콘으로 씁니다. 별도 설정이 필요 없습니다.

한글 이름 한 글자는 16픽셀에서 획이 뭉개집니다. 자모 하나나 알파벳 한 글자가 낫습니다. 16px로 실제 렌더해 보고 정하세요.

## A4. 공유 썸네일이 규격에 못 미친다

**증상** 원본 키트의 og:image는 192x192입니다. 카카오톡과 페이스북 스크래퍼는 최소 200x200을 요구해서 그 아래면 썸네일이 무시될 수 있습니다.

**고치는 법** 1200x630 이미지를 만들어 `src/app/layout.tsx`의 `openGraph.images`에 넣습니다. `width`, `height`, `alt`도 함께 지정하고, 빠져 있는 `twitter` 카드 메타데이터도 넣습니다.

`metadataBase`가 `NEXT_PUBLIC_SITE_URL`로 잡혀 있어 basePath는 알아서 붙습니다.

## A5. 방명록에 남길 수 없는데 남기라고 안내한다

**증상** Firebase 미설정 상태에서는 입력 폼이 렌더되지 않는데, 빈 목록 문구는 조건 없이 "첫 줄을 남겨 주세요!"라고 나옵니다.

**고치는 법** `src/components/LinkTree.tsx`의 `GuestbookList`에서 빈 목록 문구를 `live` 여부로 나눕니다.

## A6. 날씨를 못 불러오면 "맑음"이라고 거짓 표시한다

**증상** `FALLBACK_WEATHER`가 맑음이라, 첫 렌더와 API 실패와 모르는 WMO 코드 세 경우 모두 맑음으로 나옵니다. 비 오는 날 Open-Meteo가 죽으면 화면이 거짓말을 합니다.

**고치는 법** 중립 표시(`…`)로 바꿉니다. `labelWeatherCode`는 모르는 코드에 대해 지어내는 대신 `null`을 돌려주고, `fetchWeather`가 그 경우 throw 해서 호출부 catch로 흘러가게 합니다.

## A7. 개인 설정이 컴포넌트와 lib에 하드코딩돼 있다

키트 문서는 수정 범위를 `src/config/*`로 제한하라고 하는데, 실제로는 개인 정보가 밖에 박혀 있습니다.

**BGM 크레딧** `BgmPlayer.tsx`에 저작권 문구가 JSX로 들어 있습니다. `linktree.ts`의 `bgmCredit`으로 옮기고, 값이 비면 줄 자체가 사라지게 합니다. 크레딧이 이미 아티스트 이름을 담고 있으면 아티스트 줄을 접어 같은 이름이 두 번 나오지 않게 합니다.

**날씨 좌표** `weather.ts`의 URL 문자열에 특정 학교 좌표가 박혀 있습니다. `linktree.ts`의 `weatherLocation`(위도, 경도, 시간대)으로 올리고 URL은 조립합니다. 지역에 매인 `fetchSeoulWeather`라는 이름도 `fetchWeather`로 바꿉니다.

**방문 수 시간대** `firebase.ts`의 `seoulDay()`가 `Asia/Seoul`을 문자열로 박아 씁니다. 다른 시간대 사용자는 하루 경계가 어긋납니다. (이 저장소에서는 아직 안 고쳤습니다)

## A8. theme.ts의 색 이름과 값이 어긋난다

**증상** `rose`가 연노랑, `brown`이 파랑, `denim`이 하늘색입니다. 팔레트만 갈아끼우고 이름을 그대로 둔 탓입니다.

**고치는 법** 역할 기반 이름으로 바꿉니다. `cream`→`paper`, `rose`→`highlight`, `brown`→`accent`, `denim`→`accentSoft`, `latte`→`tint`. `LinkTree.tsx`의 `introStyle`과 `globals.css`의 CSS 변수도 함께 바꿉니다.

**함께 알아둘 것** `theme.ts`의 키 대부분은 코드가 읽지 않습니다. 실제로 반영되는 건 `paper`, `ink`, `accent`, `spiralFront` 네 개뿐이고 그마저 진입 화면에만 적용됩니다. 본문 색은 `globals.css`에 직접 박혀 있습니다. README가 "여기서 전체 색상을 바꾸세요"라고 안내한다면 사실이 아니니 문구를 바로잡으세요.

## A9. 접근성 세 가지

**파도타기 드롭다운** `<select>`의 `onChange`에서 `window.open`을 부릅니다. 키보드로 화살표를 눌러 항목을 훑으면 브라우저에 따라 항목마다 팝업이 열립니다. `aria-label`도 없습니다.

`<details>` + `<summary>` + `<a>` 목록으로 바꾸면 새 탭에서 열기, 주소 복사 같은 기본 동작도 살아납니다. select 외형은 `summary::after`로 화살표를 그려 유지합니다.

> 고정 규칙: 목록 첫 항목 `도름스 커뮤니티 나의 활동`은 순서를 바꾸거나 지우지 않습니다.

**탭** 현재 탭 표시가 `.active`의 배경색뿐이라 시각 정보에만 의존합니다. `role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`, `role="tabpanel"`을 붙입니다. `cy-back-btn`과 `cy-episode-card`에 빠진 `type="button"`도 채웁니다.

**인트로 오버레이** `.lt-intro`가 fixed로 덮기만 하고 뒤 콘텐츠는 DOM에 살아 있어, 탭 키로 안 보이는 뒤쪽 버튼에 포커스가 갑니다. `body { overflow: hidden }`은 스크롤만 막습니다.

본문 래퍼에 `inert`를 겁니다. React 19가 불리언 속성으로 지원하고, 포커스와 보조기술 접근을 함께 막아 `aria-hidden` + `tabindex="-1"`보다 정확합니다.

## A10. 코드 정리 세 가지

**화면 폭 추적** `BgmPlayer`가 `matchMedia`를 마운트 때 한 번만 읽어, 폰을 돌리거나 창을 줄여도 갱신되지 않습니다. `useSyncExternalStore`로 구독하면 짧고 `setState-in-effect`도 피합니다.

`playerVars.controls`는 iframe을 다시 만들어야 바뀌고 그러면 재생이 끊기므로 처음 값 그대로 둡니다. 이 절충은 주석에 남기세요.

**헛도는 타이머** 한 영상 안 여러 곡을 추적하는 1초 `setInterval`이, 곡마다 영상이 다른 설정에서는 매초 같은 인덱스를 다시 계산하기만 합니다. `videoId`가 겹치는 트랙이 있을 때만 타이머를 겁니다.

**secondsAt** 호출처가 없어 죽은 코드로 보이지만, 설정에서 `startAt`을 적을 때 쓰라고 둔 도구입니다. 지우지 말고 주석에 용도와 사용 예를 적으세요.

## A11. lint 설정과 CI 검사가 없다

**고치는 법** `eslint`와 `eslint-config-next`를 devDependencies에 넣고 `eslint.config.mjs`를 추가합니다.

eslint-config-next 16은 플랫 설정을 직접 내보내므로 `FlatCompat`을 쓰지 마세요. `FlatCompat` 경로는 순환 참조로 죽습니다.

```js
import nextCoreWebVitals from "eslint-config-next/core-web-vitals";
```

`no-img-element`는 `output: "export"`라 next/image를 쓸 수 없으니 끕니다. `package.json`에 `"lint": "eslint ."`를 넣고, `deploy.yml`에 Lint 단계를 `continue-on-error: true`로 추가합니다. 규칙이 자리 잡으면 이 옵션을 지우면 됩니다.

**주의** 도입하면 `?tab=` 딥링크를 읽는 곳에서 `react-hooks/set-state-in-effect`가 걸립니다. 정적 배포에서는 하이드레이션 뒤에 읽을 수밖에 없으니 사유를 적고 한 줄만 예외 처리하세요.

# B묶음: 방명록 개편

> ## 경고: 깨지는 변경입니다
>
> 원본 키트의 방명록은 **로그인 없이 이름을 적어 남기는 방식**입니다. 이 개편은 그걸 **구글 로그인 필수**로 바꿉니다.
>
> - **코드와 `firestore.rules`를 반드시 같이 배포**해야 합니다. 하나만 올리면 쓰기가 전부 실패합니다.
> - 이미 쌓인 익명 글에는 `uid`가 없어 **수정·삭제가 안 됩니다.** 읽히기는 합니다.
> - 아무나 편하게 남기는 게 미니홈피 감성이라고 본다면 **적용하지 않는 편이 낫습니다.**
>
> 사용자에게 이 내용을 전달하고 동의를 받은 뒤에만 적용하세요.

## 왜 바꿨나

이름 칸이 자유 입력이면 사칭을 막을 방법이 없습니다. 구글 로그인을 걸면 이름이 계정에서 오고, 문서에 `uid`가 남아 문제 있는 글을 추적할 수 있습니다.

## B1. 구글 로그인 기반 작성

- 로그인한 사람: 이름 칸 없이 **말 칸만**. 이름은 구글 프로필에서 자동
- 로그인 안 한 사람: 입력 칸 대신 작은 안내와 로그인 버튼
- 목록에 작성 **날짜와 시간** 표시

`firebase/auth`의 `GoogleAuthProvider`, `signInWithPopup`, `onAuthStateChanged`를 씁니다. 팝업을 그냥 닫은 경우(`auth/popup-closed-by-user`)는 오류로 알리지 않고, 팝업 차단과 승인되지 않은 도메인은 무엇을 해야 하는지 알려 주는 문구로 구분하세요.

## B2. 비밀글

체크박스를 켜고 남기면 주인장과 작성자 본인만 봅니다.

**컬렉션을 나눕니다.** 같은 컬렉션에 `secret` 필드를 두는 방법도 있지만 문제가 둘입니다. 공개 목록 질의가 `where(secret==false) + orderBy(createdAt)`이 되어 **복합 색인**을 배포해야 하고, 기존 문서에는 `secret` 필드가 없어 공개 목록에서 사라집니다.

| 컬렉션 | 읽기 | 쓰기 |
|---|---|---|
| `guestbook` | 누구나 | 로그인한 누구나 |
| `guestbookSecret` | 주인장과 작성자 본인 | 로그인한 누구나 |

**여기가 함정입니다.** Firestore 규칙은 조회 결과를 걸러 주지 않습니다. `resource.data.uid == request.auth.uid`처럼 문서마다 달라지는 조건을 걸면, 필터 없이 컬렉션 전체를 정렬해 가져오는 질의는 통째로 거부됩니다. 보는 사람에 따라 질의를 나눠야 합니다.

| 보는 사람 | 비밀글 질의 | 통과 이유 |
|---|---|---|
| 주인장 | `orderBy(createdAt) + limit` | 주인장 조건이 문서와 무관하게 참 |
| 로그인한 다른 사람 | `where(uid == 내 uid) + limit` | 규칙 조건과 필터가 일치 |
| 로그아웃 | 질의 안 함 | |

`where`에 `orderBy`를 붙이면 복합 색인이 필요하므로, 본인 글은 정렬 없이 가져와 클라이언트에서 시각순으로 합칩니다.

## B3. 수정과 삭제

|  | 수정 | 삭제 |
|---|---|---|
| 작성자 본인 | O | O |
| 주인장 | **X** | O |

주인장에게 수정 권한을 주지 않은 이유는, 남이 한 말의 내용을 바꾸면 그 사람이 하지 않은 말이 그 사람 이름으로 남기 때문입니다. 부적절한 글은 지우는 것으로 충분합니다. 다르게 보신다면 규칙 한 줄만 바꾸면 됩니다.

수정 시 바꿀 수 있는 건 `text`뿐입니다. `uid`, `author`, `createdAt`이 그대로여야 남의 글을 자기 것으로 바꾸거나 작성 시각을 조작할 수 없습니다. `editedAt`을 더해 "(수정됨)" 표시를 답니다.

## B4. 주인장 지정 (반드시 바꿔야 하는 값)

주인장 uid를 **두 곳**에 같은 값으로 적어야 합니다.

- `src/config/linktree.ts`의 `ownerUid`
- `firestore.rules`의 `ownerUid()` 반환값

> **AI에게**: 이 저장소에 적힌 uid는 progh2의 것입니다. 그대로 쓰면 남이 그 사람의 비밀글을 못 보고, 그 사람이 사용자의 비밀글을 봅니다. 반드시 사용자 본인의 uid로 바꾸세요. 아직 모른다면 빈 문자열로 두고(비밀글 기능이 꺼집니다), Firebase 콘솔의 Authentication > Users에서 확인해 나중에 채우라고 안내하세요.

한쪽만 고치면 비밀글이 실제로는 공개되거나 주인장도 못 봅니다.

## B5. 사람이 직접 해야 하는 Firebase 설정

AI가 대신 할 수 없습니다. 사용자에게 안내하세요.

1. Firebase 프로젝트 생성
2. **Authentication > Sign-in method에서 Google 사용 설정**
3. **Authentication > Settings > 승인된 도메인에 배포 주소 추가** (예: `<아이디>.github.io`). 빼먹으면 배포 사이트에서 `auth/unauthorized-domain`으로 막힙니다
4. Firestore Database 생성
5. 웹 앱 등록 후 config 값 6개를 `.env.local`과 저장소 Secrets에 입력
6. `firestore.rules` 배포

Firebase 콘솔이 처음 넣어주는 테스트 규칙은 **모든 경로에 읽기와 쓰기를 열어두고 30일 뒤 전부 막습니다.** 반드시 교체하세요.

# 적용 후 검증

```bash
npm run lint
npm run build
```

화면에서 확인할 것:

- 첫 진입에서 스파이럴 화면이 보이고, 버튼을 누르면 홈으로 넘어가는지
- 파도타기 첫 항목이 `도름스 커뮤니티 나의 활동`인지
- 이미지가 깨지지 않는지 (A2를 적용해 경로를 바꿨다면)
- 탭 키만으로 조작했을 때 인트로 뒤로 포커스가 새지 않는지

B묶음을 적용했다면 추가로:

- 로그아웃 상태에서 안내 문구만 보이는지
- 로그인하면 말 칸 하나만 나오는지
- 다른 계정으로 비밀글을 남기면 자기 글만 보이는지
- 주인장 계정에서 모든 비밀글이 보이는지
- 로그인 없이 REST로 쓰기를 시도하면 403인지

```bash
curl -X POST "https://firestore.googleapis.com/v1/projects/<프로젝트>/databases/(default)/documents/guestbook?key=<API키>" \
  -H "Content-Type: application/json" \
  -d '{"fields":{"text":{"stringValue":"테스트"}}}'
```

`PERMISSION_DENIED`가 나와야 정상입니다.
